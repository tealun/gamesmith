# 美术管线：代码绘制 → 烘焙图集 → 引擎精灵

适合一人 + AI：场景、障碍、特效用代码或简单矢量批量生产，资源小、风格统一、改动可追踪。

## 1. 视觉语言（先写规则再画）

- 用**固定颜色语义**区分可交互性：例如「深色剪影 + 红色描边 = 危险，不能碰」「黄色描边 = 可以踩」。玩家一眼读懂，色弱可辨（颜色 + 轮廓双重表达）。
- 预警全部是视觉信号（闪烁地面条、感叹号、虚线轨迹），**静音也能玩**。
- 主角颜色保留：任何场景不以主角色为主色。各场景主色互不相撞（写成表）。
- 参考作品只借视觉语法；写清「辨识点」与「禁止照搬」清单。
- 受伤表现不血腥（掉一块、夸张表情）。
- 写一份**样张**（高保真自动演示页）作为验收下限：正式素材完成度不低于样张。

## 2. 生产管线

```
绘制代码（Canvas 函数，按帧命名）──烘焙脚本（无头浏览器）──→ atlas_<name>.png + .json（帧位置、锚点、九宫格）
                                                                   │
                     core 状态 → 画面层（画什么、画在哪）→ 精灵宿主（节点池、着色、旋转、九宫格、平铺）
```

- 美术源头是代码；**换成手绘/AI 美术只需替换同名帧**，摆放逻辑不变。
- 源按 2 倍分辨率烘焙；体积紧张时个别类别降倍率（示例：远景 0.6 倍、敌人 1.5 倍、其余 2 倍）。
- 保留矢量后备画法：图集未加载时也能画（至少每帧铺满背景与地面纯色，避免残影花屏）。
- 动效（果冻感等）参数进配置，网页原型与引擎同一套参数。

## 3. 图集尺寸与拆分

- 单页上限 **2048×2048**（兼容性与显存的稳妥值；平台/机型的真实上限**待核实**）。
- 烘焙脚本**超限即失败、不写文件**，并列出最大的若干精灵（示例项目曾三次超限，靠人读日志发现，后改为脚本拦截）。可用环境变量调小上限做自测。
- 装箱用天际线（skyline）等算法；按「**公共一张 + 每场景一张**」拆分：
  - 公共：主角、道具、特效、界面、各场景色板 → 开机加载；
  - 场景：背景、地标、近景、该场景敌人 → 首次要玩该场景时加载。
- 精灵归属规则写进脚本注释（按命名前缀或配置表里的场景字段）。
- 注意：同一分包里按场景拆图集只省显存不省下载；总量逼近上限时再把每场景图集与音乐拆成独立分包。
- 新增美术前先估面积；长期逼近上限时规划多页图集。

## 4. 评审流程

1. 改绘制代码 → 烘焙（`--sheet` 输出暗底总览图）→ 预览工具截图。
2. 截图给决策人评审，记录评审结论原话与改法到美术文档（如「大方框像没做完的界面 → 改散景光斑」）。
3. 通过后同步进引擎。每完成一屏就评审一屏，**先保证每一屏都好看再加内容**。

## 5. 字体与子集

- 烘焙进图片的中文用可商用字体（示例：站酷快乐体，SIL OFL 1.1）；许可证文件入库。
- 只打包子集：维护 `<font>.chars` 字符清单，按清单生成子集（示例用 Google Fonts `css2?family=…&text=…` 下载子集）。
- 烘焙脚本扫描绘制代码里的文字，**发现子集外字符即报错**；新增文字时先加进清单再重新生成子集。
- 在无头浏览器里用 `FontFace` 加载子集，并把它挂到 canvas 字体族首位，中文走子集、西文回退。

## 6. 提审与宣传图

- 图标、截图用同一套绘制代码生成（脚本输出到 `docs/03_compliance/release/`）。
- 备案/提审截图按模块分组命名（`序号+模块_序号+内容`），**不同模块不复用同一张**；截图里的游戏名必须是当前名称。平台是否要求真机截图**待核实**，以平台要求为准。

## 7. 性能

- 特效分高/中/低三档，按机型自动选择并允许手动切换（「减少特效」开关）。
- 中低端安卓帧率需真机实测（示例项目列为待测项）。

## 示例

示例项目：几何霓虹风，4 份绘制代码 + 每场景一份场景文件，烘焙为 1 张公共图集 + 10 张场景图集（均 ≤ 2048²）；标题字从文泉驿正黑（授权不明）换为站酷快乐体子集。
