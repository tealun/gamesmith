# 内容管线：片段、关卡、求解器、生成器

适用于以「段落」组织内容的玩法：跑酷、闯关平台跳跃、弹幕躲避、节奏类、消除关卡（片段可换成「盘面」）。核心思想：**内容由数据描述，由程序验收，由生成器扩产**。

## 1. 数据模型

| 概念 | 字段（示例） | 说明 |
|---|---|---|
| 片段 chunk | `id, scene, difficulty, lengthPx, safeHeadPx, safeTailPx, entities[]` | 最小设计单元；首尾安全区保证拼接处不出事 |
| 实体 | `type (terrain/hazard/pickup), ref, x, y, w?` | `ref` 指向配置表中的类型；坐标对齐网格 |
| 关卡 level | `id, scene, speed, chunks[], savePointAfter, newContent[]` | 片段序列 + 节奏 |
| 无尽 | 难度档位、档位米数、喘息片段、场景轮换 | 导演按档位抽片段 |
| 场景 scene | `id, name, order, palette, music, code, gravityMul, densityMul…` | 场景本身也是配置 |

- 片段 id 编码含场景、难度、序号（如 `<scene>_d<难度>_<nn>`），埋点与求解器输出都直接可读。
- 关卡长度按目标时长定（示例：60–75 秒一关），中点放存档点。

## 2. 求解器：每个片段的验收线

求解器 = 在**真实玩法核心**上做搜索（不是另写一套近似物理）。示例实现是束搜索（beam search）：

- 每 0.05 秒一个决策点，动作集 `{无, 点按, 长按, 翻滚…}`；
- 每步克隆游戏状态并推进；受伤/死亡/撞墙即剪枝；
- 按状态特征（高度、速度、跳跃次数、是否着地、已触发的机关数…）去重；
- 束内保留多样性：每个「动作数」档位各留配额，免得只剩极端最优路线。

验收线（阈值按难度分档，写进配置）：

| 检查 | 含义 | 示例阈值（难度 1→5） |
|---|---|---|
| 可无伤通过 | 至少一条路线不受伤、不撞墙 | 必须 |
| 操作密度 | 最省操作路线的每秒必要操作数 ≥ 下限（防止太空太闲） | 0.9 → 2.0 次/秒 |
| 时机窗口 | 对每个必要操作做提前/推迟试探，偏移后仍能继续跑下去（模拟会顺势调整的真人）；取最宽容路线上最紧的一下 | 200 → 90 ms |
| 奖励不是陷阱 | 强制「触发每个奖励机关」的路线也能无伤通过 | 必须 |

设计要点：
- **把非伤害失误也当失败**（如撞墙弹回）：游戏里不扣血，但合格片段应能流畅通过。
- **失误恢复**：只验证最优路线不够。真机出现过「钻出矮顶 → 撞墙 → 被推回 → 不能起跳」的死循环。补救方式：核心修复 + 回归测试（撞墙后任意时刻点一下都能过）+ 静态规则（出口到下一面墙留足距离）；可进一步让求解器验证「每个撞墙点一次点击内可恢复」。
- 物理修正要同步验收线（示例：低重力场景浮空久、操作自然少，密度线乘 0.7）。
- CLI：全量模式（退出码反映是否全部达标，用于 CI）+ 单片段模式（打印输入时间轴、每个操作的窗口，可选打印轨迹）。全量很慢时支持前缀通配（`<scene>_*`），并在窗口已够宽时提前停止。
- 求解器不放随机掉落物（如攒命道具），这些不影响片段验收。

骨架：`templates/solve.mjs`。

## 3. 静态规则（配合求解器）

求解器抓「能不能过」，静态校验抓「合不合理」，便宜且即时：

- 地面生物只能站在从地面立起的实心块上，不能站在悬空平台上（飞行类除外）。
- 奖励机关后方 N 秒（按测试跑速换算）落地区无墙、矮顶、尖刺、敌人。
- 跳台从高处起跳滞空更长，一串跳岛高度差不宜大，否则节拍断裂（求解器会以密度不达标暴露）。
- 高处路线必须有奖励，否则没人走。

## 4. 生成器：从骨架派生新场景

扩场景时不从零画片段：

1. 选一个**骨架场景**（片段已全部过求解器）。
2. 场景规格文件 `scene_specs/<scene>.json` 写清：场景配置、新敌人、地形外观名、音乐、可掉落道具、惊吓事件、**各阶段敌人映射**（骨架角色 → 新敌人）与**替补列表**。
3. 生成器保留骨架的地形、收集物、补给，按映射替换敌人；按阶段（每关一阶段）控制新内容数量；生成关卡表（难度模板 + 存档点）。
4. `--solve`：逐片段跑求解器，不过的换替补敌人重试；仍不过的**舍弃**，并重建关卡。
5. 跑配置校验 + 求解器全量复核 + 预览截图。

注意：替换时检查原型限制（例如只有静止类可以站在块上；新敌人宽度与骨架不同可能卡位）。生成器是幂等的 upsert，可以重复运行。

## 5. 教学节奏

- 每关**新内容 ≤ 2 项**；一个新能力连同它克制的新威胁算 1 个教学单元；收集物不计入；基础地形不计入上限。
- 新内容三步出现：**单独、慢速、前后留白 → 与已掌握内容安全组合 → 高潮段有压力组合**。
- 特殊动作（如翻滚钻洞）在专门一关教，之前的片段不出现它。
- 由校验脚本检查每关新内容数和首次出现位置。
- 引导之外：首次拾取弹提示 + 道具说明页（见 `feel-and-ux.md`）。

## 6. 场景配置化

场景的名称、主题色、顺序、埋点场景码（上线后不可改）、敌人前缀、音乐、物理修正、可掉落道具都在 `scenes.json`；界面、绘制、音乐、埋点、校验、预览全部从它读。新增场景检查：缺片段库/音乐/外观/调色板/前缀 → 校验逐条报错。

## 7. 片段编辑工具

可选：做一个网页「片段工坊」（网格摆放、可达高度参考线、即时试玩、导出 JSON）；也可用 Tiled 等通用编辑器导出。示例项目选自制网页工具，Tiled 为备选。工具里同步落实静态规则，免得到校验时才报错。

## 示例

示例项目：首个场景手工设计 24 个片段，全部过求解器；后续 9 个场景由生成器从其骨架派生，每场景约 50 个片段（过不了的自动换替补或舍弃），每场景 3 关、每关 16 片段、第 8 片段后存档点。
